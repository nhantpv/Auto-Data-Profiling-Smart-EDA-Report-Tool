### Design decisions locked in this plan

1. **Provenance enum** → `OBSERVED | INFERRED | INDETERMINATE | DERIVED_CROSS_TABLE` (per §3 + §9.6). `LLM_GUIDED` has zero usages → removed (deviation doc records it).
2. **Disposition** (§5.5d): new `Disposition` enum + `disposition` field on `AnomalyRecord`/`IntegrityError`/`IssueSummary`. Fixed map from the arch (`MISSING_COLUMN, UNIQUE_VIOLATION → REVIEW`; `NOT_NULL_VIOLATION, IMBALANCE → PREPROCESS`) extended with a deterministic default table (documented as Heuristic): CRITICAL schema blockers (`PK_DUPLICATE, PK_NULL, ORPHAN_FOREIGN_KEY, MISSING_COLUMN→REVIEW per arch`) → BLOCK; `MISSINGNESS, DUPLICATE, CONSTANT_COLUMN → PREPROCESS`; `HIGH_CARDINALITY, TYPE_MISMATCH, NON_UNIQUE_PARENT_PK → REVIEW`; `OUTLIER_ENSEMBLE → SIGNAL` (P7: outlier ≠ error); severity fallback CRITICAL→BLOCK, HIGH/WARN→REVIEW, INFO→SIGNAL.
3. **NON_UNIQUE_PARENT_PK** becomes an `IntegrityError` with severity **HIGH** (deviation note: arch doesn't fix a severity; declared-PK duplicates already fire CRITICAL `PK_DUPLICATE` at L2b, so the runtime check on possibly-inferred edges uses HIGH to avoid auto-NOT_READY from inferred relationships). The offending edge is **skipped** (arch: "bỏ qua cạnh đó").
4. **§9.6 artifact**: new `cross_table_correlations.json` written in multi mode, with `CrossTablePair` records carrying `status ∈ {OK, TOO_FEW_UNITS, NULL_OVERLAP, VALIDATION_FAILED}` (+ `skip_reason` free-text extension), `n_independent`, `join_cardinality` (from graph edges), `unit_of_analysis="parent"`, `provenance=DERIVED_CROSS_TABLE`, and `llm_plan{model,temperature,seed,timestamp}`. The existing `cross_table_analysis.json` stays as the safe-join diagnostics artifact (documented).
5. **L3b consumes graph output**: `run_multi` builds the graph first, then passes only relationships whose edges survived (non-unique-PK edges dropped) into `run_cross_table_analysis`, along with the edges for cardinality stamping.
6. **Verdict ordering in `run_multi`**: graph + NON_UNIQUE findings are produced **before** `aggregate(...)` so they reach the verdict (today the verdict is computed before the graph exists).
7. **Single per-run FindingRegistry**: `run()`/`run_multi()` create one registry; `build_data_quality_findings` and `calibrate_columns` accept it as a parameter (default `None` → local registry, backward compatible). Multi-table registers **prefixed** records (`table.col`) so cross-table dedup can't collide.
8. **Confidence scheme (Heuristic v0, documented)**: observed measurements → 1.0; MAR-escalated MISSINGNESS → provenance INFERRED, confidence 0.7; `OUTLIER_ENSEMBLE` keeps mean ensemble display score; mechanism confidence on `ColumnStats`: MAR 0.7, MCAR_CONSISTENT 0.6, INDETERMINATE 0.3.
9. **L1 Full multi**: `_profile_data_quality` defaults to full; `run_multi(..., profiling_minimal: bool = False)` + CLI `--profile-minimal` escape hatch; Tab 2 = per-table ydata reports in one self-contained HTML with a `<select>` switcher.
10. **DB ingestion**: `src/ingestion/db_reader.py`, SQLite via stdlib (path `.db/.sqlite/.sqlite3` or `sqlite:///` URL); `export_database(source, out_dir)` emits sanitized-name CSVs + a generated DBML (match-by-construction), then `run_db()` feeds `run_multi`. `postgresql://`/`mysql://` raise `NotImplementedError` naming the extension point. `DATABASE_URL` env var is the default for `--db` when the flag has no value… **no** — keep it explicit: `--db <path-or-url>` only; `DATABASE_URL` documented in `.env.example` as the conventional place to keep the URL, read by `run_db` when `--db` is passed the literal `env:DATABASE_URL`. Simpler: `--db` accepts the URL; `.env.example` documents `DATABASE_URL=` as a convenience the *user* can interpolate. No code reads it (documented).
11. **Precise Mode**: webapp two-pass flow matching the existing job model — Quick run produces suggestions; `GET /api/jobs/{id}/schema-suggestions` reads them; `POST /api/jobs/{id}/schema-confirm` writes `confirmed_schema.json` and submits a **new** job from the old spec (mirrors `retry`). `GET /api/jobs/{id}/report` serves the tabbed HTML.
12. **Env var names** per §5.9(i): `SMART_EDA_ANALYST_MODEL`, `SMART_EDA_EDITOR_MODEL` (the `SMART_EDA_L4_*` names are removed — migration note).
13. **Threshold routing**: shared `get_threshold_registry()` singleton in `config/threshold_registry.py`; consumers read at call time with their current defaults as fallback. New registry default keys: `cross_table_min_units=30`, `anomaly_contamination=0.05`.
