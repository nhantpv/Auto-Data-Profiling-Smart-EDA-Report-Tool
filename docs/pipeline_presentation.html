1. Bức Tranh Tổng Thể (The Big Picture)

Toàn bộ pipeline được điều phối bởi tệp run_pipeline.py, đi qua 4 tầng xử lý chính:

  • 0 Layer 0: Ingestion - Đọc dữ liệu & Schema (Bóc tách file).
  • 1 Layer 1+2: Engines - Thống kê & Bắt lỗi dị biệt, lỗi thiết kế DB.
  • 2 Layer 2.5: Severity Stack - Chẩn đoán mức độ nghiêm trọng (Bệnh nhẹ hay nặng?).
  • 3 Layer 3: Ontology - Đóng gói kết quả thành JSON chuẩn mực.

2. Layer 0: Data Ingestion (Nạp dữ liệu)

Nhiệm vụ: Chuyển đổi các định dạng file vật lý thành cấu trúc dữ liệu chuẩn để Python xử lý.

  • src/ingestion/registry.py: Lễ tân điều phối. Tự động nhận diện `.csv`, `.xlsx`, `.parquet`. Tích hợp Smart Sampling (chống tràn RAM).
  • src/ingestion/readers.py: Công nhân đọc file thực tế, tự động fix lỗi font (UTF-8, Latin-1).
  • src/ingestion/schema_reader.py: Adapter Pattern, đọc file bản vẽ `.dbml` hoặc `.sql` (DDL).

Input

- data.csv, data.xlsx (Dữ liệu) - schema.dbml, schema.sql (Bản vẽ)

Output

- df: pandas.DataFrame (Bảng thật) - schema: UnifiedSchemaResult dict

3. Layer 1 & 2: Profiling & Anomaly

Nhiệm vụ: "Khám bệnh" trên bảng dữ liệu để tìm ra các con số thống kê và các dòng dữ liệu dị biệt.

  • src/engines/profiling_engine.py: Chạy ydata-profiling. Lấy số dòng, số cột, % rỗng, tự tính số dòng trùng lặp (bỏ qua ID).
  • src/engines/anomaly_engine.py: Chạy Hội đồng AI (IForest + ECOD + LOF). Lấy điểm Z-Score tích hợp (Max) để tìm ra Outliers.

Input

- df: pandas.DataFrame

Output

- profile_result: dict (Chứa thống kê) - anomaly_result: dict (Chứa index dòng rác)

4. Layer 2 (tiếp): Schema Validation

Nhiệm vụ: Đối chiếu dữ liệu thực tế xem có làm đúng thiết kế bản vẽ Database không.

  • src/engines/schema_engine.py: Trái tim đối chiếu đa bảng.
    • Chạy 7 Validators: Kiểm tra cột thừa/thiếu, sai kiểu dữ liệu, PK bị Null hoặc Trùng.
    • Chạy Multi-table Check: Soi các bảng với nhau tìm Khóa ngoại mồ côi (Orphan FK).

Input

- df / list of dfs (Dữ liệu thực tế) - schema dict (Từ schema_reader.py)

Output

- Danh sách IntegrityError objects (Mô tả chi tiết cột sai, số dòng sai)

5. Layer 2.5: Severity Stack

Nhiệm vụ: Chẩn đoán mức độ nghiêm trọng của từng lỗi (CRITICAL, HIGH, WARN, INFO).

  • src/severity/missingness.py: Phân loại cơ chế thiếu dữ liệu (MCAR/MAR/MNAR).
  • src/severity/calibrator.py: Tra bảng quy định (Threshold) để dán nhãn mức độ lỗi cho từng cột.
  • src/severity/compound.py: Nâng mức cảnh báo nếu 1 cột dính nhiều lỗi liên tiếp.
  • src/severity/aggregator.py: Phán quyết sinh tử cho toàn bộ Dataset (READY hay NOT_READY).

6. Layer 3: Ontology & Export

Nhiệm vụ: Đóng gói toàn bộ kết quả một cách chuẩn mực nhất để gửi cho LLM (Layer 4 sau này).

  • src/ontology/models.py: Đặc tả hợp đồng Pydantic. Đảm bảo cấu trúc JSON không bao giờ sai lệch. Gắn chuẩn DAMA (Completeness, Validity...).
  • src/ontology/findings_builder.py: Gộp toàn bộ Profile + Anomaly + Missingness thành JSON hoàn chỉnh, trích xuất top 10 dòng lỗi mẫu.
  • src/engines/visualizer.py: (Tích hợp ở Layer 3.5) Tự động vẽ Scatter Plot bôi đỏ điểm Outlier và đính kèm vào báo cáo.

7. Orchestration: run_pipeline.py

Đây là nhạc trưởng điều phối toàn bộ các nhạc công bên trong thư mục `src/`.

  • Luồng chính (Hàm run): df = load_csv() ➔ profile = run_profiling() ➔ anomaly = run_anomaly_detection() ➔ mechs = detect_missingness() ➔ findings = build_data_quality_findings() ➔ Write JSON

Global Input (Từ Terminal)

python run_pipeline.py data.csv output_dir

Global Output (Ra thư mục đĩa)

1. data_quality_findings.json 2. dataset_verdict.json 3. schema_evaluation_findings.json (Nếu có)
