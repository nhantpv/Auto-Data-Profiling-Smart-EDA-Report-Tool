# Section 1 — Academic Papers

- **“Dead or Alive: Continuous Data Profiling for Interactive Data Science”** (Will Epperson *et al.*, IEEE VIS 2023) – *Problem:* Analysts must manually plot distributions and summary stats to profile data, a tedious process leading to infrequent profiling. *Approach:* Introduces **AutoProfiler**, a notebook-integrated system that **continuously profiles** data by live-updating visual summaries and stats (distributions, correlations, missing values, etc.) alongside the code. The system’s UI allows filtering and exporting code; a user study found users discovered 91% of potential findings using AutoProfiler【8†L18-L26】【8†L27-L31】. *Relevance:* Example of automating EDA visualization and profiling with minimal user effort. ArXiv: *https://doi.org/10.48550/arXiv.2305.07126*【8†L18-L26】. **[verified]**

- **“Profiling Relational Data – A Survey”** (Z. Abedjan *et al.*, VLDB J. 2015) – *Problem:* Data exploration is time-consuming; profiling (finding column metadata, keys, patterns) is essential but complex. *Approach:* A comprehensive survey of **automated data profiling tasks** for relational data, categorizing single-column (e.g. histograms, types, correlations) and multi-column (e.g. functional dependencies, associations) profiling, as well as approximate and interactive techniques【127†L1-L4】. It summarizes algorithms and use cases for each task. *Relevance:* Foundational taxonomy of profiling tasks (e.g. nulls, duplicates, dependencies) that underlie EDA and quality checks【127†L1-L4】【18†L156-L160】. [DOI] VLDBJ 24(4):557-581 (2015). **[verified]**

- **“Large Language Model-based Data Science Agent: A Survey”** (K. Chen *et al.*, arXiv 2025) – *Problem:* LLMs are increasingly used to automate data science workflows, but research on LLM agents in data science is scattered. *Approach:* Surveys recent work on **LLM-based agents** for data science, from both the *agent* perspective (design: role, execution, knowledge, reflection) and *data science* perspective (workflows: preprocessing, modeling, evaluation, visualization)【129†L49-L58】. Proposes a dual-framework linking agent design principles with DS tasks. *Relevance:* Summarizes architectures and tasks of LLM agents for analysis (e.g. text-to-SQL, model generation, narrative), framing how an “LLM Data Scientist” agent could work【129†L49-L58】. arXiv:2508.02744. **[verified]**

- **“Towards Automated Cross-domain Exploratory Data Analysis through LLMs”** (J.-P. Zhu *et al.*, VLDB 2025) – *Problem:* Crafting SQL queries and choosing charts for EDA across diverse databases is hard; users may express goals vaguely or not know schema details. *Approach:* Presents **TiInsight**, an LLM-driven EDA system. It structures the process hierarchically: it infers data context from schema, decomposes user intent into sub-queries (question, SQL, charts), then generates SQL via a text-to-SQL model (TiSQL) and selects charts via an LLM (TiChart). The system returns intermediate results (SQL and visuals) for user feedback. *Relevance:* Exemplifies an end-to-end LLM-augmented EDA pipeline that translates natural language goals into SQL and visualizations, achieving ~91–90% accuracy on benchmark cross-domain queries【22†L25-L31】【22†L39-L43】. ArXiv:2206.12909 (accepted VLDB 18(12), 2025). **[verified]**

- **“Tasks and Visualizations Used for Data Profiling: A Survey and Interview Study”** (R.A. Ruddle *et al.*, TVCG 2023) – *Problem:* Practitioners spend much time “data profiling” (characterizing distributions, finding missing/outliers) but do so in ad-hoc ways; visualization is often underused in profiling. *Approach:* Conducts a survey of 53 data analysts and follow-up interviews to compile the range of **profiling tasks and visual techniques** used in practice. It identifies common tasks (e.g. counting nulls, histograms, unique values) and what charts analysts typically use for them【35†L77-L85】【35†L90-L98】. *Relevance:* Empirical inventory of real-world EDA and profiling tasks and visualizations, highlighting user needs and gaps (e.g. under-utilized plots)【35†L77-L85】【35†L90-L98】. [DOI](https://doi.org/10.1109/TVCG.2023.3299452). **[verified]**

- **“InReAcTable: LLM-Powered Interactive Visual Data Story Construction from Tabular Data”** (G. Aodeng *et al.*, UIST 2025) – *Problem:* Crafting a coherent visual “data story” from many potential insights in a table is hard, especially as user goals evolve. *Approach:* Introduces **InReAcTable**, a system that first builds an “insight graph” of candidate findings (structural filtering) and then applies a retrieval-augmented LLM to semantically filter and rank insights relevant to the user’s query. It provides an interactive UI where recommended insights (charts+explanations) can be accepted or refined. User studies show it helps users iteratively compose visual narratives. *Relevance:* Illustrates LLM-assisted filtering and ranking of data insights for narrative reporting, connecting tabular patterns to textual explanations【38†L51-L60】【38†L61-L69】. [ArXiv](https://doi.org/10.48550/arXiv.2412.06819). **[verified]**

- **“LIDA: A Tool for Automatic Generation of Grammar-Agnostic Visualizations and Infographics using LLMs”** (V. Dibia, ACL 2023 Demo) – *Problem:* Generating good visualizations from data requires enumerating goals and coding charts. *Approach:* Presents **LIDA**, an LLM-based pipeline with four modules: a Data Summarizer (text summary), a Goal Explorer (enumerates chart ideas via LLM), a VisGenerator (generates code for charts, refined via a critic LLM), and an Infograph module (renders charts into styled infographic images). A web UI lets users interactively refine charts and styling. *Relevance:* Demonstrates generating visualization code and narrative descriptions via LLMs for EDA; output includes charts and image-based infographics (similar to automated report visuals). **[verified]** (Video/Demo and code: https://github.com/microsoft/lida).

- **“Large language models (LLMs) on tabular data: Prediction, generation, and understanding — a survey”** (X. Fang *et al.*, TMLR 2024) – *Problem:* LLMs show promise on tabular tasks (e.g. prediction, QA, data-to-text), but there’s no unified overview of techniques, benchmarks, or failures. *Approach:* Reviews recent LLM applications on tabular data, including tasks like forecasting, table QA, and data summarization. It catalogs models, datasets, metrics, and identifies limitations (e.g. LLM output accuracy, need for better tabular alignment). Provides taxonomy and suggests future directions. *Relevance:* Broad survey of LLM capabilities and challenges on tabular data tasks, which encompasses narrative generation and reasoning needed for automated EDA【131†L421-L430】. [Amazon Sci.] **[verified]**

- **“DataPrep.EDA: Task-Centric Exploratory Data Analysis for Statistical Modeling in Python”** (J. Peng *et al.*, SIGMOD 2021) – *Problem:* Existing EDA tools are either too “plot-focused” (low-level) or too high-level (lacking fine control for modeling needs). *Approach:* Introduces **DataPrep.EDA**, a declarative Python API for specifying common EDA tasks (e.g. summarizing distributions, handling missing values) at any granularity with one function call【135†L51-L60】. Implements these tasks efficiently using Dask-based pipelines. In experiments, DataPrep.EDA significantly outperformed Pandas-profiling in speed and user experience【135†L64-L68】. *Relevance:* Example of an automated EDA library that streamlines common profiling tasks programmatically (though without narrative generation)【135†L51-L60】【135†L64-L68】. ArXiv:2104.00841. **[verified]**

# Section 4 — Gap Analysis

1. **Well-covered capabilities:** Most tools handle *basic descriptive statistics and visualizations*. Open-source profilers (YData, Sweetviz, DataPrep) automatically compute counts, distributions, nulls, duplicates and render charts or HTML reports. LLM/data agents can translate NL to code or SQL (Mode AI Assist, PandasAI) and generate simple plots. Data quality frameworks (Great Expectations, Deequ) provide missing/null detection and alert on rule violations. AutoML/EDA libraries (DataPrep.EDA) automate many standard EDA tasks. Auto-charting (Lux, AutoViz) gives immediate visuals.

2. **Weakly covered / missing capabilities:** A cohesive *end-to-end* pipeline is rare. Few tools *automatically detect outliers or complex anomalies*, schema drift, or cardinality issues without user rules. Narrative interpretation of findings is mostly absent in open tools: only LLM-based proof-of-concepts (e.g. LIDA) attempt chart explanations, but commercial BI (Tableau Pulse, Cognos Watson) offers more polished insight generation. Interactive feedback (refining queries) is limited outside research prototypes. Integration of continuous profiling (drift alerts) with LLM summaries is not seen in a single product. Handling *large-scale databases* securely with generated code is under-explored (most LLM demos use small CSVs).

3. **Potential differentiators:** Building an LLM “Senior Data Scientist” that not only profiles but also critically interprets results is key. Differentiators could include: **Automated insight filtering:** only presenting *statistically significant or actionable findings* to avoid LLM hallucination noise. **Schema-drift detection:** continuous monitoring of table schemas and alerting. **Explainability/traceability:** linking narrative statements to actual stats or charts. **Interactive refining:** let users ask follow-ups that refine anomalies or drill into causes. **Data security:** integrating on-prem LLM or self-hosted agents to safely query real DBs. A strong UI that combines profiling metrics with LLM commentary (with citations) could set the project apart.

4. **Unresolved technical risks:** LLM hallucinations about data (e.g., inventing trends or misinterpreting stats) remain a risk; few solutions enforce grounding in actual values. Security of running generated SQL/python against live databases is a concern (SQL injection, unauthorized queries); existing tools mostly trust LLM outputs or limit context. Scaling to very large tables is unaddressed: most profilers sample or struggle with >10^6 rows. Also, maintaining up-to-date profiles in streaming or dynamic schema environments is unsolved. Finally, user trust in automated narratives is low unless metrics are verifiable (some mention of citations in Tableau Pulse, but commercial tools often “explain” with no proof).

# Section 5 — Suggested Reading Order

1. **Abedjan *et al.* 2015 (“Profiling Relational Data – A Survey”)** – Foundational taxonomy of profiling tasks (single vs multi-column), giving context on what automated profiling must achieve【127†L1-L4】.  
2. **Ruddle *et al.* 2023 (“Tasks and Visualizations for Data Profiling”)** – Empirical list of real-world profiling tasks and vis techs used by analysts【35†L77-L85】, to align tool design with user needs.  
3. **Peng *et al.* 2021 (“DataPrep.EDA: Task-Centric EDA”)** – Concrete system for automating EDA tasks in Python, demonstrating how to declaratively specify and compute statistics efficiently【135†L51-L60】.  
4. **Epperson *et al.* 2023 (“Dead or Alive: Continuous Data Profiling”)** – Shows an interactive notebook tool (AutoProfiler) that continuously updates data profiling visuals, inspiring UI integration ideas【8†L18-L26】.  
5. **Zhu *et al.* 2025 (“Towards Automated Cross-domain EDA through LLMs”)** – Latest example of an LLM-driven pipeline solving text-to-SQL and chart selection for exploratory analysis, illustrating modern LLM capabilities in EDA【22†L25-L31】.
